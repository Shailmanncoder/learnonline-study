# Detailed roadmaps and Companion video suggestions

Roadmaps accept any learning/project goal, requirements, daily time, a start date and either exact days or a target date. Exact days take priority. The former 120-day product cap is removed; valid calendar bounds, finite storage and provider quotas still apply. Target dates are exclusive (a 62-day plan has exactly days 1–62).

`POST /api/study/roadmap/generate` generates at most three days per request. Inputs: `examName` (goal), `topics` (requirements), `days`, `startDate`, `hoursPerDay`, `nextDay`, `previous` (last 42 days), optional `curriculum` (supplied contents), and the returned `outline`. A validated, gap-free full-duration phase outline is created first and reused in every batch to prevent premature wrap-ups and repeated mini-courses. Each returned day includes an explanation, worked example, practice questions with answers/checking rubrics, timed tasks, focus, deliverable and measurable check. The server allocates the daily minutes and rejects missing material, unsupplied chapter references, unverified links and unmarked exact repetition. A second AI call reviews correctness and topic alignment before the batch is accepted; it is not independent textbook verification. The server validates consecutive day numbers, exact batch size and daily minute totals. A malformed generation is retried once; it is never filled with generic placeholder days or labelled complete.

The browser sequentially requests batches, shows completed/total counts, saves each completed batch under the signed-in user's local storage key, and supports pause/resume after errors. Keep the tab open while generating. Completion checkboxes, incremental display, JSON download and calendar export are available. Calendar export is disabled until the full plan is generated. Storage is local to this browser, not synchronized across devices; download large plans if browser storage fills. Starting a new plan keeps one previous-plan backup before replacement. Refresh restores the saved plan; generated-day and studied-day counts are separate. A browser lock prevents simultaneous continuation across tabs. This is not a durable server job: generation requires an open tab and available provider quota. Old plans retain a warning; regenerate to get the new material checks.

Video suggestions live only inside Companion (YouTube button or a request such as “Suggest a YouTube video for Class 11 CBSE motion in a straight line in Hindi”). Configure `YOUTUBE_API_KEY` on the backend with YouTube Data API v3 enabled. No key is embedded in the frontend. Search returns up to ten candidates; videos.list verifies available public, non-live videos. AI compares metadata and may select only IDs in the retrieved candidates. Responses include channel, date, duration, language and a match explanation. They do not claim to have watched videos, checked full transcripts, or verified the latest NCERT edition. Without a key or on lookup failure, the reply supplies an explicitly unverified YouTube search link.

Basic “Class 12 motion” prompts ask whether the learner means Class 11 kinematics or Class 12 charged-particle motion. Reference: https://www.ncert.nic.in/desm/pdf/desm_s_physics.pdf. An older upload can still be useful, and a new upload alone is not evidence of current-edition coverage. Fully verified latest-edition video alignment remains a separate requirement needing a current corpus and transcript-level checking.

Validation (2026-10-01): deterministic tests cover 62 and 123 exact days, 1000-day input acceptance, leap years, missing material, false completion, malformed outlines, unsupported chapter references, repeated topics, daily minute totals and failed content review. A real provider-backed two-day maths plan was completed in the browser; lesson, example, practice/answers and checked-day persistence were inspected. A full 123-day provider run has NOT been validated after these changes.

Short follow-ups such as “one shot” retain the video topic and class. Explicit remembered video-language preferences are applied unless the latest request changes them. The English subject is not treated as a request for English speech. Language evidence comes from titles/descriptions plus uploader metadata; conflicting or unknown evidence is not promoted into a confirmed match. No transcript-level spoken-language guarantee is made.
