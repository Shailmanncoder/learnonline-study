# LearnOnline audit and local remediation — 1 October 2026

## Scope and verification boundary

Inspected the public `https://learnonline.study/` site, the local application, the pasted 123-day roadmap, frontend routing/rendering/storage, authentication, teacher/student authorization, Teaching Studio, Companion memory and streaming, video selection, roadmap generation, account deletion and dependency advisories. Changes extend the current application and preserve the existing uncommitted feature work. No production records were changed and no push or production deployment was performed.

Authenticated checks used an isolated SQLite database and disposable accounts on a separate loopback preview. The ordinary local app is served at `http://127.0.0.1:3000/`. This is an audit of the paths listed here, not a guarantee that every feature or every possible vulnerability has been exhausted.

## Confirmed issues and fixes

| Area | Failure found | Change |
|---|---|---|
| Teacher permissions | Knowing a class code could grant teacher membership; some teacher routes did not enforce the live teacher role | Owner-approved join requests and router-wide live-role checks |
| Session authorization | Deleted accounts and stale JWT roles could outlive database changes | Resolve the current account and role on authenticated requests; deleted accounts return 401 |
| Outages | Database failure could be misreported as a bad token | Authentication dependency failures return 503; profile connection errors preserve the local session |
| Homework | Submission did not consistently enforce publication and active-class state | Reject draft/archived-class submissions and oversized payloads |
| Account deletion | New teaching records could outlive the account/classroom | Remove resources, attendance, drafts, join requests and usage records transactionally |
| Companion progress | Shared public request IDs could collide between accounts | Account-scoped IDs resolve to unique internal run handles |
| Chat history | Long threads reopened with the oldest 200 messages | Load the latest 200, then return them in chronological order |
| Video language | The English subject could override requested Hindi speech | Separate subject from spoken language; apply explicit remembered video preferences |
| AI output | Markdown renderer allowed active HTML from generated responses | Shared sanitizer after Markdown/math restoration; safe plain-text fallback |
| Profile and content rendering | Names, biographies, notes and some class/homework text entered HTML or inline handlers | Escape text/attributes; move homework actions to data attributes |
| Leaderboard privacy | Anonymous API requests received registered email usernames, biographies and avatar values | Require authentication; hide other accounts' emails, bios and avatar URLs |
| Leaderboard logic | Teacher accounts mixed into student rankings and ties differed outside the top list | Student-only ordering by XP then ID, matching current-user rank calculation |
| Dashboard identity | A fresh login could show sample name, email, XP and level until refresh | Refresh account UI immediately and use neutral initial markup |

## The 123-day roadmap failure

The supplied plan had only 14 generated days, repeated introductory material, and instructions to solve or grade exercises/quiz questions that were not actually provided. A generic instruction such as “verify all answers” is not a usable checking guide. A title saying 123 days does not establish that the remaining days exist or that the syllabus is current.

The revised generator:

- Builds and validates a gap-free outline for the full requested duration.
- Generates three detailed days per request, each with an explanation, worked example, concrete practice and worked answers/checks.
- Allocates the daily time on the server and validates consecutive days and exact batch size.
- Rejects unsupported chapter numbers, unavailable answer keys, missing material and unmarked exact repetition.
- Runs a second AI correctness/content review; rejected batches are retried once, then pause without losing earlier days.
- Labels the source basis honestly. Pasted contents help scope the plan but do not prove current NCERT alignment.
- Restores saved plans, distinguishes generated versus studied days, labels partial downloads, locks simultaneous continuation and enables calendar export only for complete plans.
- Preserves an older-plan warning; prior generated content is not retroactively certified by the new checks.

Practical limits still exist: calendar bounds, provider quota, response/storage size, generation time and an open browser tab. The second AI review can also miss errors. The application does not promise unlimited computation or verified textbook accuracy.

## Validation

- Full isolated regression suite: 195 tests, 193 passed, 2 skipped because no ingested source library is available in the fixture.
- Added regressions for teacher approval and revoked roles, draft/archived homework, deletion cleanup, long-thread ownership/history, stream ID isolation, spoken-language preferences, exact 123-day structure, failed material review, browser account isolation and leaderboard privacy/ties.
- Real browser checks: fresh student login; actual name/0 XP/level 1; safe literal rendering of markup in names/bios; correct ranking banner; owner approval UI; reachable teacher mobile logout; developer skills saved across reload and used by the test selector; `/developer/tests` and `/teacher/studio` reload.
- Real provider-backed two-day maths roadmap completed; included explanations/examples/practice and completion-checkbox persistence were checked. Full 123-day generation was tested deterministically, not with 123 live provider-generated days.
- Browser harness used the actual app renderer: active HTML/javascript links were removed, while normal Markdown, a normal HTTPS link, code text and math delimiters survived.
- Syntax checks and `git diff --check` passed. Compatible dependency updates were followed by the full suite and native image processing and a real local embedding (384 finite dimensions). `npm audit fix` reports zero remaining vulnerabilities; this is advisory coverage, not proof of application security.

## Remaining operational/product work

1. **Release:** these changes are local. The public site retains its deployed version until a release is made and checked.
2. **Provider capacity:** the local Gemini service returned quota-exceeded responses during investigation; the configured fallback completed the short roadmap. Reliable large plans require sufficient quota and a durable background-job design. No billing/model settings were changed.
3. **Current textbooks:** the configured NCERT/Postgres service was unavailable locally. Full corpus completeness/current-edition checks and the two dataset-dependent tests remain unverified; no database dump was restored over existing data.
4. **Video quality:** title/description/uploader metadata is not proof of actual speech, full teaching quality or latest-NCERT coverage. Transcript-level checking and a maintained syllabus source are still needed for stronger claims.
5. **Files:** Teaching Studio accepts file attachments within its limits, but Office/PDF/image contents are not all automatically extracted there. Malware scanning/quarantine and scalable object storage remain operational work.
6. **Email and identity:** signup OTP/SES remains deferred as requested. Production anti-abuse/identity verification and an approved privacy/retention policy need a separate rollout; legal review placeholders are not completed legal advice.
7. **School workflows:** academic-year promotion, teacher replacement, guardian consent/linking and individualized intervention tracking are not represented as completed features.
8. **Scale:** progress and limits stored in one process need shared storage/sticky routing for multiple workers. SQLite checks do not prove production MySQL migrations, multi-worker behavior or a 10,000-user load capacity.
9. **Developer practice:** AI grades remain provisional; this portal is not an authoritative certification system. Browser-local skill/history persistence is not cross-device synchronization.

## Rendering dependency

`frontend/vendor/purify.min.js` is the pinned DOMPurify 3.4.16 distribution, with its license alongside it. Source and safe-use guidance: https://github.com/cure53/DOMPurify. Markdown is sanitized after placeholder restoration, and math rendering does not enable trusted HTML.
